## What changed and why

Three non-deletion requests were caught by broad deletion-verb patterns. The corrected intent checks distinguish correction without removal, marketing-only opt-out, and information access explicitly excluding erasure. A separate explicit account-deletion request can still authorize deletion.

Six subjects had query identity and resource state on different lines in escaped cloud envelopes or syslog records. The parser now decodes the message and joins by service, request/span ID and instance/pod. It carries only earlier query context, never future state. A lookup start is not a presence observation. Source classification context is retained without carrying response states between events.

The remaining catalog-linked object is independently visible in a selected object-storage screenshot panel. The exact filename, size and version ground presence; the activity link supplies subject/resource membership. Unique aliases, successful exclusive-ownership catalog links and both time cutoffs are required. No hardcoded case IDs, fabricated resource IDs, reference labels or workflow-result shortcuts were introduced.

## Interpretation

Local structural validity improved, while public raw step/field agreement decreased. The extra catalog-grounded finding also affects a public sample subject. We retain that disagreement and do not suppress evidence to maximize the sample score. The supplied public reference also includes a policy disagreement around analytics deletion versus anonymization. These are unresolved semantic limitations; no hidden-case correctness or leaderboard outcome is claimed.

The 100 synthetic variants and 115 robustness probes are developer-authored and were reused during development. They are separate populations, not external independent validation. External GDPRbench, FEBRL4, ALCE and AgentDojo suites were not run natively. No prior timing or speedup claim is transferred to this changed checkpoint.
